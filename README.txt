netbench - замер железа и линии + оптимальный basic.cfg для arma 3 сервера

запуск (одна строка, четыре аргумента):
  netbench_run.cmd 200 127.0.0.1:2302 50 150
    1) uplink Mbit/s - если пропустить, скрипт измерит линию сам (замер upload
       грузит канал ~8 секунд, ещё ~8 download, на живом сервере в это время
       лагают). с переданной цифрой тест скорости НЕ запускается вовсе, поэтому
       когда на сервере играют, строку надо начинать именно с числа
    2) ip:port живого сервера - откуда берутся реальные слоты (A2S_INFO);
       в каждом шаге спрашиваются и порт игры, и порт игры +1, потому что BI
       отвечает на запрос именно на +1, а сам игровой порт на него не отвечает.
       если молчат оба и адрес локальный, в
       отчёте пишется, слушает ли вообще что-то на этой машине udp в диапазоне
       BI (порт игры -1 .. +4): пустой список = сервер на другой коробке и надо
       передавать его настоящий адрес, а не 127.0.0.1. если же сокет привязан к
       адресу сетевой карты, а не к 0.0.0.0, запрос повторяется на этом адресе
       (такой сервер 127.0.0.1 просто не слышит) и в отчёте называется адрес,
       который ответил
    3) --players: сколько слотов этот бокс уже держит (для калибровки железа).
       в модель число слотов берётся с живого сервера; это число - запасной
       вариант, когда A2S молчит, и если оно разошлось с ответом сервера, в
       логе стоят обе цифры и сказано, какую взяла модель
    4) ffa_evo_allunitmax: какой потолок юнитов стоит на этом боксе

прогон без калибровки:   netbench_run.cmd 200 127.0.0.1:2302
прогон только с замером: netbench_run.cmd
адрес можно ставить и первым - тогда замер линии скрипт делает сам:
  netbench_run.cmd 127.0.0.1:2402 40 150
число в первой позиции - это всегда uplink, адрес - всегда с двоеточием;
мусор в числовой позиции скрипт не превращает в nan, а печатает эту строку
запуска и выходит.

если замер upload не удался (до тестового хоста нет пути, линия не отвечает),
скрипт не выдаёт допущение за твою линию: в строке uplink пишет почему
не измерилось, а таблица размещения и basic.cfg помечены "LINE NOT MEASURED" -
100 Mbit/s там встроенное допущение, а не твой тариф. тариф можно задать сам
(netbench_run.cmd 200 127.0.0.1:2402), тогда пометки исчезнут и сравнение
"влезает / не влезает" считается по нему.

замер в течение дня (мод не нужен, в сервер не пишется ничего - только
счётчики ос снаружи + a2s-запрос):
  netbench_watch.cmd                        сутки, строка каждые 30 с
  netbench_watch.cmd 720                    12 часов
  netbench_watch.cmd 1440 30 127.0.0.1:2302 127.0.0.1:2402
  netbench_watch.cmd 127.0.0.1:2302 127.0.0.1:2402
                                    только адреса: сутки и 30 с остаются по
                                    умолчанию
  netbench_watch.cmd report         сводка по уже собранным строкам
  каждый адрес опрашивается ещё и на порт выше: паров 2302+2303 и 2402+2403
  хватает с любой стороны - написал игровой порт или порт запроса, сервер всё
  равно попадает в список. порт, который уже назван или стоит над другим
  названным, второй раз не добавляется: сумма игроков считается по списку, и
  один сервер в нём дважды урезал бы кбит/с на игрока вдвое.
  окно лучше не закрывать; раньше времени остановиться - создать пустой файл
  out\watch\STOP. ctrl-c убивает только съёмщик, собранные строки остаются,
  потом можно вызвать report.
  снимает: байты адаптера (это фактическая полоса наружу), cpu и ram процесса
  сервера, сколько игроков и слотов на каждом a2s-адресе. в конце считает
  кбит/с на игрока по бакетам игроков и по часам, сверяет с моделью и пишет
  out\watch\basic.cfg уже из измеренного, а не из модели. если цифр мало или
  на серверах никто не играл - пишет почему, и basic.cfg не трогает.
  линия и точка модели (heavy/busy/quiet, smooth/balanced/save, слоты, дальность)
  для сравнения берутся из out\report.json после одиночного прогона; --uplink,
  --world, --prio и --players рядом с node перекрывают их. без известной линии
  строка "влезает/не влезает" не печатается. слоты сводка всё равно берёт с
  живых ответов за день: поменяешь maxPlayers в server.cfg в течение суток -
  сводка подхватит новое число, а не вчерашнее.
  win7 / server 2008: байты считаются через netstat -e (командлетов адаптера там
  нет), cpu и ram процесса - обычные, всё работает; в столбце src будет
  proc-only+netstat-e.
  cpu и ram пишутся только по процессу сервера (имя содержит "server"). в строках,
  где такого процесса на машине не было - сервер в этот момент рестартнулся или
  упал - cpu и ram остаются пустыми, а байты адаптера считаются: сумма всех
  процессов коробки не является процессом сервера. в сводке такие строки
  посчитаны отдельно ("no server").

консоль и язык вывода:
  файлы всегда русские - netbench.log, out\watch\summary.txt, комментарии в
  basic.cfg. на современных окнах скрипт рисует русский через powershell.
  на win7 / vista / server 2008 / 8 / 8.1 такая консоль utf-8 не рисует, поэтому
  там подписи на экране печатаются по-английски, а русский вариант той же строки
  идёт в лог. это делают флаги --lang en и --tee; в батниках они включаются
  сами, отдельно ничего задавать не нужно.
  в начале прогона печатается "console: old windows console detected".
  и экран, и рантайм решает одна строка ver, то есть одно и то же определение
  лежит в picknode.cmd - вручную его можно перебить только для экрана:
    set NETBENCH_LEGACY=1     английский экран, русский лог
    set NETBENCH_LEGACY=0     обычный вывод через powershell
  а если ошибается само определение винды (на локализованной системе строка ver
  бывает без скобок), есть отдельный переключатель для него:
    set NETBENCH_MODERN=1     брать node24 (win10 и новее)
    set NETBENCH_MODERN=0     брать node12 (win7 / 8 / 8.1)
  имена с самой машины (версия ос, план питания, сетевая карта) перевести
  нельзя: на старом экране они печатаются латиницей ("Maykrosoft Windows 11
  IoT Korporativnaya"), в логе и report.json остаётся оригинал. в конце прогона
  скрипт говорит, сколько таких строк было пересобрано в латиницу.
  сам движок: netbench.js --lang en --tee netbench.log ...

архив и node: один netbench_all.zip работает на всех поддержанных виндах и на
линуксе -
внутри два рантайма, node12 (win7 / vista / 2008 / 8 / 8.1) и node24 (win10,
server 2019+, включая 2025), а picknode.cmd сам решает, какой из них стартует,
по строке ver и проверкой запуска. выбирать архив не нужно и node ставить не
нужно - кроме линукса: там своих бинарников нет, рантайм берётся из
дистрибутива, см. раздел ниже. если ни одного из двух рантаймов в папке нет, подхватывается node.exe
рядом со скриптами, потом netbench\node\node.exe, потом node из PATH - старые
раскладки папок остаются рабочими. и то, и другое только для 64-битных виндов:
на 32-битной системе скрипт об этом скажет. сам код синтаксиса новее 12 не
требует, так что один и тот же файл живёт на обоих рантаймах; проверка -
selftest_a2s.js и --check прогоняются на каждом.

линукс: тот же js, те же подписи, тот же csv. под линукс не переписано ничего,
кроме сбора чисел - модель, парсер a2s и вывод остались общими, поэтому суточный
лог с линукса и с виндовса сравнивается построчно. вместо powershell и netstat
всё читается из /proc и /sys (nixstat.js):
  железо      /proc/cpuinfo (модель, ядра, треды - "cpu cores" не суммируется,
              он повторяется на каждый логический), /sys/.../cpufreq,
              cache/index*, /proc/meminfo, /etc/os-release, /sys/class/dmi/id
  линия и день /sys/class/net/<if>/statistics по физическим картам (виртуальные
              - lo, docker0, veth, bond - в сумму не входят; если физических
              вообще нет, берётся всё, и источник это подписывает), плюс
              /proc/<pid>/stat и statm по процессу сервера
  порты       /proc/net/udp и /proc/net/udp6 - то же самое, что на винде даёт
              netstat -ano, включая привязку сокета к адресу карты
  имя процесса ищется по "arma" и в comm, и в argv[0] из cmdline: ядро режет
  comm до 15 символов, и на полном имени arma3server_x64 фильтрация бы не
  срабатывала. cpu и ram считаются по сумме utime+stime в тиках и по resident
  из statm - это те же величины, что на винде, поэтому строка "server ram" в
  сводке означает одно и то же на обеих осях.
  список портов процесса остаётся пустым, если сервер запущен другим
  пользователем: /proc/<pid>/fd без прав того же юзера (или ptrace) не
  читается. на cpu и ram это не влияет.
запуск тот же, только .sh:
  sh netbench_run.sh 200 127.0.0.1:2302 50 150
  sh netbench_run.sh 127.0.0.1:2402 40 150     адрес первым - и тогда линия
                                               меряется сама
  sh netbench_watch.sh                          сутки, строка каждые 30 с
  sh netbench_watch.sh 1440 30 127.0.0.1:2302   то же с адресами
  sh netbench_watch.sh report                   вывод из уже собранных строк
весь дневной прогон без терминала:
  nohup sh netbench_watch.sh > watch.out 2>&1 &
аргументы понимаются ровно как в батниках: адрес можно ставить первым (в нём
есть двоеточие, в числе минут его нет), каждый названный адрес спрашивается ещё
и портом выше, мусор в числовой позиции - ошибка, а не nan.
.sh не пересохраняют из notepad: он возвращает переносы в crlf, и тогда ядро
отказывается читать первую строку ("bad interpreter"). правка - только
редактором с lf. если хочется без "sh" впереди: chmod +x *.sh и ./netbench_run.sh
node в архив не кладётся: оконные node12 и node24 - это оконские бинарники, под
линукс рантайм берётся из репозитория дистрибутива. picknode.sh ищет node в
PATH (сначала node, потом nodejs), проверяет, что он 12-й ветки или новее, и
если его нет - называет пакет, который надо поставить.
язык экрана решает локаль, а не версия системы: в LANG=C (чистый server
install, cron, su) терминал utf-8 не рисует, и тогда на экране английские
подписи, а в лог идёт русский копиат - ровно как на старых окнах. в начале
прогона печатается "console: this locale cannot draw utf-8". перебить руками:
  export NETBENCH_LEGACY=1     английский экран, русский лог
  export NETBENCH_LEGACY=0     обычный utf-8 экран
  export NETBENCH_MODERN=1/0   то же одним флагом
всё остальное про вывод, файлы и сводку - см. разделы выше: под линукс там
меняются только пути (out/watch вместо out\watch) и источник чисел.

какой архив брать:
  netbench_all.zip         один на все ос: win7 / 2008 / 8 / 8.1, win10 /
                           server 2019+ (включая 2025) и линукс. внутри оба
                           оконных рантайма, .cmd и .sh обёртки; под линукс
                           node ставится из дистрибутива
  netbench_win7.zip        win7 / 2008 / 2012: внутри node 12.22.12 x64,
                           ничего докидывать не надо (только винда)
  netbench_portable.zip    win10 / server 2022+: внутри текущий node (v24), на
                           win7 он не запустится (только винда)
  netbench.zip             только скрипты, node ищется в path или в netbench\node\

что получается:
  out\basic.cfg          готовый файл настроек, кладёшь рядом с exe сервера
  out\report.json        все замеры и расклад по каждому ключу
  out\calibration.json   опорная точка железа, перекинь её на второй бокс
  out\watch\samples.csv   строки дневного замера (по одной на интервал)
  out\watch\summary.txt   сводка дневного замера, обновляется на ходу
  out\watch\basic.cfg     basic.cfg из измеренной полосы (если цифр хватило)
  netbench.log           весь прогон, utf-8
  netbench_watch.log     весь дневной замер, utf-8

обратно автору: netbench.log, out\report.json, out\basic.cfg
                и для дневного: out\watch\samples.csv + summary.txt

проверка парсера без сервера: node selftest_a2s.js
